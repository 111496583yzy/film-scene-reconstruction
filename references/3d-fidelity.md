# 精细三维拉片：不是多放几个方块

用户给了精细参考时，先拆参考的组成，再搭场景。比较的是可见空间、人物调度和分析图的完成度，不是仅看 WebGL 是否运行或 mesh 数量。

## 依据场景需要补齐的层次

| 层次 | 需要能看清什么 | 常见的低质量替代 |
|---|---|---|
| 空间骨架 | 门洞、墙厚、台阶、台面高度、主要开口之间的关系 | 空地板加三面无区分的墙 |
| 布景层 | 可见的窗框、帘褶、墙板、家具、挂画等识别性结构 | 所有物件都用同一种色块 |
| 人物层 | 身体、四肢、坐姿或站姿、朝向、主要人物服装识别 | 头部小球加直立柱子；盘坐者画成悬空坐椅 |
| 小件层 | 对当前参考有辨识意义的席垫、杯盘、桌上物等 | 靠增加毫无来源的装饰填满房间 |
| 摄影层 | 有体积的机身、镜头、支撑器材、可读编号与取景体积 | 漂浮的箭头或只有文字没有器材 |
| 灯光层 | 各类光源/附件能通过造型区分：顶灯、窗光面、灯架、黑旗等 | 全部变成同一种软箱并声称是现场灯具 |
| 信息层 | 当前机位突出，其他机位弱化，灯组编号可查，主角不被标签挡住 | 每个节点都放长句、彼此压盖 |

不是每个场景都要有这些物件。有依据才添加；隐蔽区域和精确尺寸未知仍须保留。参考作者图中的方案可以借鉴，但要引用来源、写明是参考推演，不当作电影画面或幕后资料的证明。

## 视角和画幅是精细度的一部分

- 像剖面片场图的参考，优先用**真正三维的正交相机**总览，以减少近大远小、看清两端和密集调度；它仍能环绕和缩放，不是平面投影画出来的假 3D。
- 用 `scene.overview` 设置起始 position / target，让主要空间轴的屏幕方向接近参考。不要让入口、舞台和视线方向在没有说明时反过来。
- 总览按可见物件范围取景，剖掉的墙体不能造成大面积空白边。报告的“放大片场”提供独立大图，便于看清人群和编号。
- 只有“进入机位”使用透视相机，并保持原片宽高比。正交/透视切换不能让机位数据变动。
- 摄影视锥是三维体积；在分析总览中裁到房间和地面以内，别出现穿到地板下面、比整个片场还大的三角。未标定视角仍须有 proposal 标注。

## 人群不能用性能换质量

`scene.extras` 可为每个人设置 `pose`、`seatedStyle`、`headingDeg`、`modelHeight`、服装/皮肤/头发颜色、`hairStyle`。盘坐用 `seatedStyle:"cross-legged"`，坐椅用 `"chair"`；需要席垫和杯盘时显式设置 `seatPad / offerings`，不默认往所有电影里塞。

后台会按姿态和材质组合做实例化渲染，同组共享立体部件；席垫和杯盘也批量绘制。密度应该由参考决定；实际配置了多少模型不代表真实演员人数。不要为了声称“精细”凭空生成角色身份或数量。

## 细节配置要可复用，不把样片写死进引擎

- `scene.floorColor / floorTiles` 控制地面材质与砖缝；间隔为相对单位。
- `elements` 可设置 `detail:"panelled" / panelCount`、`model:"aircon" / "light-frame"`。模型程序只认识通用造型，具体数量与位置来自 scene 数据。
- `textureData` 只允许内嵌 PNG/JPEG。可从本地参考中裁取已获准分析的材质或图像局部，记录来源与裁切，不能用低清纹理声称高精度。保持报告离线，不加载远程材质。
- `scene.annexes` 可配置入口外走廊的相对体积与台阶。没有参考时不自动添加。
- `scene.fixtures` 是整场共享的灯组，逐镜 `lighting` 是该镜额外的方案。每组有 id、label、position、target、role、claim，以及可选的 shape、size、elevation、offset、showBeam。
- 灯组 shape：softbox、ceiling-panel、bulb、strip、window、flag。offset 是相对世界坐标三维偏移，用于已明确的门外等位置，不是米。
- `setup.color` 可以稳定区分机位组，但相同机位回切必须保持编号、位置与颜色的一致性。当前机位才显示醒目视锥，其余组保留弱化编号和器材。

## 实际视觉验收

在参考近似视角、相近尺寸下取一张截图，逐项比：主体空间比例、主要物件、人物姿态与密度、摄影机/灯具识别度、标签可读性、画面填充程度。

再做功能回归：放大/返回、环绕/缩放、正交总览→透视机位→返回、换镜和播放、灯组开关、灯位清单、浅色实际拖选文字、390 窄屏。自由旋转到极端角度后需要用户缩小是正常三维观察行为；默认总览和交付截图必须完整。

结束条件：参考中关键可见层次已覆盖；脚本回归通过；实际 UI 操作与截图复查完成；余下差距明确说明。未测试的路径不称通过，不用“可旋转”代替精细度验收。
